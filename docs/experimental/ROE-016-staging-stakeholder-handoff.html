1. Why we built staging

Rasaoi ranks restaurants and builds meal “plates” from real menus. New AI and data features are powerful — and risky if they invent dishes or break the live app.

Staging is a copy playground: same kind of app, separate servers, separate data. We turn new features on there first. Production stays on the proven path until you approve.

2. Advantage comparison (old vs staging)

Plain language: what production does today vs what staging adds, and why it helps.

Feature Before (production today) After (staging now) Advantage for Rasaoi
Safe place to try changes Most tests hit the same live path or local machines. Own website + own database. Flags on only for staging. We can break things safely. Customers never feel experiments.
Which AI model answers Ask Always Gemini only. Smart router can try other models; if they fail, Gemini still answers. Less lock-in to one vendor. Better uptime. Room to pick cheaper/faster models later.
Dish knowledge for ranking Fixed file built offline (culinary-index.json). Slow to refresh. Live database overlay of dish knowledge on top of that file. Menus and nutrition facts can update without a full rebuild. Ranking stays richer.
Nutrition / blood-sugar help Heuristics + Gemini estimates. Gaps can be guessed. 3-step food breakdown; unknown bits go to a quarantine (held aside). Linked into the GL lens. Honest about missing data. Less fake nutrition. Safer for wellness claims.
Learning from user feedback Check-ins are write-only. Hard for tools to read safely. Secure mirror + script turns weak ratings into written “don’t do this again” rules. Closed loop: real user pain becomes automated test cases.
Stress-test for bad / weird Asks Small manual checks. 520 chaotic test Asks; simulator scored 100% (goal was ≥98%). Catch invented dishes and regional mistakes before they hit users.
Keeping menus fresh Lab / Firecrawl / manual ingest. Weekly Apify job + webhook; knowledge updates first. Live menu publish needs a human promote step. Automation without silent menu inventing. Catalog stays trustworthy.
Secrets & keys Prod env only. Separate .env.experimental + staging secrets (USDA, OpenAI, Anthropic, Apify…). Keys never mix with production. Easier to revoke staging-only access.
Ship process Prod CI on develop / main. Dedicated GitHub Action deploys staging branch → v0-rasaoi-staging.vercel.app. Every staging push can auto-update the practice site.
Guardrails policy Pairings rules in code + tests. Same rules + standing “no invented dishes” Cursor policy + impact audits. Agents and humans share one clear “do not invent plates” contract.

3. Features live on staging (detail)

EXP-T8 Dedicated staging site

What: https://v0-rasaoi-staging.vercel.app talks only to staging Supabase.

Advantage: Zero risk to rasaoi-delta. Stakeholders can click the same Ask → Reading flow.

EXP-T2 / T10 Model router

What: Ask, glycemic, and menu ingest go through a router. Gemini is the safety net.

Advantage: We can trial OpenAI/Anthropic on staging without stranding users if a key fails.

EXP-T1 Dynamic culinary overlay

What: Reading loads dish knowledge from staging Postgres and overlays the static index.

Advantage: Fresher dish facts. If remote load fails, the old static file still works.

EXP-T3 Nutrition quarantine + blood-sugar lens bind

What: Unmapped ingredients are stored as quarantine rows, not invented macros. Lens can use verified binds.

Advantage: Better honesty for “healthy / GL” asks. No silent fake calories.

EXP-T5 Telemetry → guardrails

What: Check-ins mirror to an experimental feedback table. A script can feed low scores into negative_guardrails.xml.

Advantage: Bad outcomes become permanent regression tests.

EXP-T4 / T9 Adversarial simulator (520 seeds)

What: Automated “chaotic Ask” corpus. Gate passed at 100% (target ≥98%).

Advantage: Proof we resist inventing Dal Tadka on South Indian menus, carrier-only plates, etc. (heuristic gate — not the same as live LLM QA).

EXP-T7 / T11 Apify menu pipeline + weekly cron

What: Webhook + Actor schedule Sunday 06:00 UTC. Writes knowledge first. Promoting into live menu_items needs an explicit promote command.

Advantage: Menus can refresh automatically while plates still come only from approved catalog dishes.

EXP-T6 Isolation

What: Experimental migrations and secrets stay off production. Docker is optional; staging uses remote Supabase.

Advantage: Clear wall between experiment and money path.

5. What staging is not (important)

  • Not production. Do not treat staging data as customer truth.
  • Apify cron does not auto-publish scraped dishes onto live plates. Promote is manual on purpose.
  • Simulator 100% is a heuristic gate. We still want a short human “plate soak” (oceany / sweet / Jain / South Indian) before merge.
  • No merge to develop until you approve after that soak.
Ask of stakeholders: Spend 10–15 minutes on the staging site with a few real Asks (oceany, something sweet, Jain/birthday, South Indian). Confirm plates look menu-true. Then say Pass or note issues. After Pass, engineering can open the develop PR.
